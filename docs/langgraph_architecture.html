Architecture Documentation

PromptPal LangGraph
Architecture

Migration from isolated Python classes to a LangGraph state-passing DAG — eliminating redundant DB queries and enabling parallel execution.

Why we changed

Three Problems with the Original Architecture

The original five "agents" were plain Python classes. They shared no runtime state, so every agent re-queried the database independently.

6×

Redundant DB Queries per Request

short_term_summary was computed 3 separate times per /chat/ request — once inside TrainerAgent.generate_learning_content(), once inside generate_follow_up_questions(), and once inside NavigatorAgent.get_next_learning_options(). Each call hit PostgreSQL + called GPT-5-mini to summarize the last 5 interactions. That's 6 redundant DB hits and 3 redundant LLM calls every single request.

~8s

Forced Sequential Execution

follow_up_questions and next_topic_suggestions are logically independent — neither depends on the other's result. But the original main.py ran them sequentially: trainer → follow_up → navigator → save_module. The two parallel-eligible steps wasted 3–5 seconds of wall-clock time per request.

200

Lines of Orchestration in One Endpoint

The /chat/ endpoint in main.py mixed route handling, agent orchestration, error recovery, DB writes, and response formatting all in one 200-line function. There was no way to test individual steps in isolation or observe what happened at each stage without inserting print statements.

DB + LLM Calls per /chat/ request

❌ Before (Sequential)

  • interactions SELECT → GPT-5-mini [TrainerAgent: content]
  • users SELECT long_term_summary
  • interactions SELECT → GPT-5-mini [TrainerAgent: follow-up]
  • users SELECT long_term_summary
  • interactions SELECT → GPT-5-mini [NavigatorAgent]
  • users SELECT long_term_summary
  • progress SELECT completed_modules

4 redundant calls (highlighted) consuming ~2s extra

✅ After (LangGraph)

  • interactions SELECT → GPT-5-mini [fetch_summaries_node]
  • users SELECT long_term_summary
  • progress SELECT completed_modules
  • ~~interactions SELECT~~ → read from state
  • ~~users SELECT~~ → read from state
  • ~~interactions SELECT~~ → read from state
  • ~~users SELECT~~ → read from state

3 unique calls total — fetched once, shared via state

Shared State

PromptPalState — Who Reads, Who Writes

The TypedDict state object flows through the entire graph. Each cell shows whether a node reads (R) or writes (W) that field.

State Field Type fetch_summaries trainer follow_up navigator save_module
INPUT — Set at request time by /chat/ endpoint
user_id str R R R R R
user_role str — R R R —
query str — R R — R
selected_document_ids List[str] — R — — —
MEMORY — Fetched once by fetch_summaries_node, then shared
short_term_summary str W R R R —
long_term_summary str W R R R —
completed_modules List[str] W — — R —
CONTENT — Written by trainer_node
conversational_response str — W R — —
learning_content List[dict] — W — — —
PARALLEL OUTPUT — Written concurrently by follow_up & navigator nodes
follow_up_questions List[dict] — — W — —
next_topic_suggestions List[dict] — — — W —
RESULT — Written by save_module_node
module_save_result dict — — — — W

W = node writes this field to state  |  R = node reads this field from state  |  — = node doesn't touch this field

Node Reference

Node Details

Each node is a pure function PromptPalState → dict. Dependencies are injected via closure factories in chat_graph.py.

📊
summary_node.py → make_fetch_summaries_node()
fetch_summaries_node

Entry node. Runs first. Fetches all memory context a single time and places it in shared state — this is the fix for the 6× redundant DB call problem.

Reads from State

  • user_id

Writes to State

  • short_term_summary
  • long_term_summary
  • completed_modules

External Services

  • PostgreSQL: interactions
  • PostgreSQL: users
  • PostgreSQL: progress
  • GPT-5-mini (summarize)
🎓
trainer_node.py → make_trainer_node()
trainer_node

Core lesson generation. Reads pre-fetched summaries from state (no DB call). Routes to CLEAR or PromptCoach prompt strategy, calls Gemini 2.5 Pro with Google Search grounding.

Reads from State

  • query
  • user_id
  • user_role
  • short_term_summary
  • long_term_summary
  • selected_document_ids

Writes to State

  • conversational_response
  • learning_content

External Services

  • Weaviate: CoreConcept
  • Weaviate: PromptGuide
  • Weaviate: UserDocument
  • Gemini 2.5 Pro + Google Search
  • PostgreSQL: interactions (write)
❓
followup_node.py → make_follow_up_node()
follow_up_node ⚡ Parallel

Runs in parallel with navigator_node. Generates 3 short follow-up prompts (5–6 words) using GPT-4. Uses lesson content and summaries from state — no extra DB calls.

Reads from State

  • query
  • user_role
  • conversational_response
  • short_term_summary
  • long_term_summary

Writes to State

  • follow_up_questions

External Services

  • GPT-4
🧭
navigator_node.py → make_navigator_node()
navigator_node ⚡ Parallel

Runs in parallel with follow_up_node. Embeds user context, searches Weaviate UseCase collection with near_vector, then generates 5 AI task suggestions via GPT-4.

Reads from State

  • user_role
  • short_term_summary
  • long_term_summary
  • completed_modules

Writes to State

  • next_topic_suggestions

External Services

  • Weaviate: UseCase (near_vector)
  • Weaviate: CoreConcept (near_vector)
  • OpenAI text-embedding-3-small
  • GPT-4
💾
save_module_node.py → make_save_module_node()
save_module_node

Join point — runs after both parallel branches complete. Embeds the user's query and checks cosine similarity against existing completed_modules. Saves to DB only if semantically unique (similarity < 0.75).

Reads from State

  • user_id
  • query

Writes to State

  • module_save_result

External Services

  • PostgreSQL: progress.completed_modules (write)
  • OpenAI text-embedding-3-small (cosine check)
Integration

How the Graph Replaces the Endpoint Logic

The compiled graph is invoked with an initial state dict. All orchestration logic moves out of main.py.

❌ Before — main.py /chat/ endpoint
@app.post("/chat/")
async def chat(req, bg: BackgroundTasks):
    # ~200 lines of mixed logic:
    trainer_response = trainer
      .generate_learning_content(
        user_id, user_role, content,
        selected_documents
      )
    # internally calls summary_agent ×2

    follow_up_questions = trainer
      .generate_follow_up_questions(...)
    # internally calls summary_agent ×2 again

    next_options = navigator
      .get_next_learning_options(...)
    # internally calls summary_agent ×2 again

    module_result = summary
      .save_completed_module(...)

    bg.add_task(cache_prompts_task, user_id)
    return { ... }  # assemble manually
✅ After — main.py /chat/ endpoint
@app.post("/chat/")
async def chat(req, bg: BackgroundTasks):
    result = chat_graph.invoke({
        "user_id":     req.user_id,
        "user_role":   req.user_role,
        "query":       req.content,
        "selected_document_ids":
                       req.selected_documents or [],
        # remaining fields start empty
        "short_term_summary": "",
        "long_term_summary":  "",
        "completed_modules":  [],
        "learning_content":   [],
        "conversational_response": "",
        "follow_up_questions": [],
        "next_topic_suggestions": [],
        "module_save_result": {},
    })
    bg.add_task(cache_prompts_task, req.user_id)
    return {
        "answer":            result["conversational_response"],
        "follow_up_questions": result["follow_up_questions"],
        "suggestions":        result["next_topic_suggestions"],
        "learning_options":   [],
    }
Impact

Before vs. After Comparison

Metric ❌ Before ✅ After (LangGraph)
DB queries per /chat/ request 7 (4 redundant) 3 (all unique)
LLM calls for summarization 3× GPT-5-mini per request 1× GPT-5-mini per request
Follow-up + Navigator execution Sequential (~3–5s wasted) Parallel (concurrent branches)
Estimated /chat/ latency ~8–12s (sequential) ~5–7s (parallel + no redundant calls)
Orchestration location ~200 lines mixed into main.py ~15 lines in main.py + graph files
Node testability Must mock entire endpoint Each node testable independently
Observability Manual print() statements LangSmith: per-node I/O tracing
Streaming support Not possible graph.astream() — native token streaming
Adding a new processing step Edit 200-line endpoint function Add node + edge in chat_graph.py
